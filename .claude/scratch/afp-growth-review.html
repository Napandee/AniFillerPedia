What grows AniFillerPedia from here

A prioritized read on the site as it stands today — browsed live, not from the roadmap — against the two real competitors and the three people it needs to win over: the casual viewer, the power contributor, and the third-party developer.

The build is genuinely ahead of most funded products at this stage: a clean public API, moderation and trust-weighted voting, five-language i18n, accessibility passes, conditional-request caching, and an MCP server already mid-build in an open worktree. What it doesn't have yet is evidence that anyone outside the maintainer has used any of it — every one of the 137 series on the site was hand-loaded by Andreas in batches, and the brand-new /activity feed, built specifically to show community edits, currently shows none. That gap — not a missing feature — is the throughline of this review.

Quick wins

canon-grade

Cheap, low-risk, mostly finishing work already scoped or reusing data already computed.

Finish the MCP server (#178)

Effort S-MImpact: dev trust

An uncommitted worktree already scaffolds 5 read-only tools over the existing public API. This is the one feature that genuinely has no equivalent at either competitor — animefillerlist.com has no API at all, and Simkl's catalog API is licensing-gated. Shipping it makes AniFillerPedia the only agent-native filler/canon source that exists.

Bias check: aligned — this is finishing already-scoped, already-started work, not a new bet.

Turn on real traffic analytics

Effort SImpact: enables everything below

Cloudflare Web Analytics — cookieless, already on the account, one script tag. Right now there is no visibility into whether anyone is finding the site, where from, or where they drop off before contributing. Every other item on this list is a guess without it.

Bias check: the one explicit exception worth taking. This isn't a feature bet on unproven demand — it's the instrument that tells you whether any other bet paid off. Skipping it is itself a decision to keep flying blind.

Filler-free watch-order page per show

Effort SImpact: SEO wedge

From the project's own idea backlog (#156): a server-rendered canon+mixed-only episode checklist, strict/inclusive toggle, purely derived data. "One Piece filler-free watch order" is a search query that already exists independent of this project — this packages an answer as its own linkable page, distinct from the series dashboard.

Bias check: aligned, and the demand signal already exists in search behavior — this isn't speculative.

Needs-corroboration view

Effort SImpact: onboarding

Also from #156: surface every episode still resting on a single source — source_count is already stored. This is the scoped, low-stakes "citation needed" task a first-time contributor needs. Today the only on-ramp is picking up an entire unresearched show, which is a much bigger ask than the site currently has evidence anyone is willing to make.

Bias check: aligned — reuses data already computed, aimed directly at the zero-contributions problem.

Fix #170 — ETag stripped by gzip

Effort SImpact: dev trust

Already filed: Caddy's gzip rewrites the ETag on the public domain, breaking conditional-request caching. Small, but it directly affects the third-party-developer persona this review is meant to serve — an API that advertises ETag support and then silently breaks it undercuts exactly the credibility #178 is trying to build.

Bias check: aligned — a bug fix, not a feature bet.

Manual outreach — post the link where the question already gets asked

Effort SImpact: highest-leverage item here

Not a build: a few hours placing the site in r/anime resource threads, MyAnimeList filler-list forum threads, and a couple of large anime Discord servers' resource channels. SEO is built (#63) and waiting on search ranking to work. This is the only item on the list that puts the URL directly in front of the audience today, rather than waiting for search to find it.

Not a build — no bias check applies.

Meaningful investments

mixed-grade

Real engineering weeks, justified by a specific persona or a documented recurring cost.

Discord bot — "is episode 143 of One Piece filler?"

Effort MImpact: distribution

From #156, currently parked as low-priority. Read-only against the existing public API; Discord OAuth is already wired. This is the single best-fit distribution channel available: the exact question this project exists to answer is one people already ask, constantly, in Discord servers. A bot answering in-channel reaches people where they're already asking, instead of waiting for them to think of a website.

Bias check: recommended exception. It's filed as "not yet scoped, not a priority" — worth pulling forward specifically because the site currently has zero deliberate distribution channels, and this is the cheapest one that reaches the actual audience.

Embeddable filler-status widget (/embed/{slug})

Effort MImpact: backlinks + SEO

Also from #156, unblocked now that slugs exist (#116). Close to free marketing value for every wiki, blog, or forum that embeds it, and it's a genuinely good answer for a developer who wants the data without touching the API at all.

Bias check: aligned — low-risk, and unlike a leaderboard it doesn't need an existing community to pay off.

Structured "anime canon" sub-tag

Effort S-MImpact: data quality

CLAUDE.local.md documents the same judgment call — does anime-original content replace the source or run alongside it — being made from scratch across FMA 2003, Ao no Exorcist, Ouran, Railgun, Akame ga Kill!, and Noragami, with at least one after-the-fact reversal. A lightweight additive tag turns a proven, recurring inconsistency into queryable data, without touching the locked-in canon/filler/mixed model.

Bias check: aligned — not speculative; addresses a cost the project's own history already paid five times over.

"Adopt a show" claim on /needs-research

Effort MImpact: contingent

Let a logged-in contributor mark one of the 56 needs-research series as claimed, visible to others. Today, every loaded series was researched by one person. There is no evidence any external contributor has ever completed the cross-referencing workflow end to end — a claim system prevents duplicate effort once real contributors show up, and makes the queue read as an actual invitation rather than a passive list.

Bias check: aligned only if sequenced after a real distribution push (the Discord bot / outreach above) — built in isolation, against zero current contributors, this would be exactly the kind of building-ahead-of-demand the project's own convention warns against.

A real working example against the API/MCP

Effort S-MImpact: dev conversion

A small companion repo — a real Discord bot or CLI script — referenced from docs/API.md. The docs are already thorough (#138), but a developer converts faster from something they can fork and run than from endpoint reference alone.

Bias check: aligned — cheap developer-relations work riding on #178, which is already committed.

Bigger bets

filler-grade

Judgment calls, not obviously ready to build — real payoff, real risk, or not fully Andreas's decision alone.

Semi-automated research pipeline

Effort LImpact: the real ceiling

Extend the already-built Wikipedia-episode-table scraper into a pipeline that also drafts candidate filler/canon calls from the guide sites already used for corroboration, producing a reviewable draft per show instead of a fully hand-compiled one. Coverage (137 of many thousands of eligible shows) sourced entirely by one person across ~13 manual batches is the actual ceiling on every other lever here — SEO, the Discord bot, and developer integrations all multiply whatever fraction of anime is covered, which today is small.

Bias check: worth the exception — this addresses a resource constraint the review itself keeps surfacing, not a feature nobody asked for. Needs a human-in-the-loop review step, not full automation — this project's own history includes real scraper bugs (title truncation, row-boundary bleed) that only got caught by a careful second pass.

A real "state of the data" trust page

Effort MImpact: credibility

Coverage %, per-series last-verified date, dispute rate, and the multi-source cross-referencing methodology, as a real page — not buried in commit history. The actual differentiator from animefillerlist.com isn't just "has an API" — it's cited, cross-referenced, audit-trailed data. That story currently lives in a private local file, invisible to any real visitor.

Bias check: aligned — surfaces data already collected, no new capability needed.

Reopen the Simkl conversation, from strength

Effort — outreachImpact: high or zero

The original research explicitly parked "ask Simkl" for later. Months on, the position has changed — real coverage, a public API, and soon MCP-native access is a materially stronger opening than the original "ask a bigger player for a favor," and Simkl already owns the audience this project doesn't have.

Bias check: Andreas's call specifically, not something to initiate independently — the same guardrail already on record.

Finish standing up commercial licensing

Effort SImpact: free option value

The mechanics were decided (#21); the actual contact channel — Cloudflare Email Routing for licensing@ — was never stood up. This doesn't touch the no-paywall stance at all; it closes the gap between "we'll license this commercially" and there being any live way to actually ask.

Bias check: aligned — finishing a decision already made, not a new bet.
Overall assessment

The biggest unrealized opportunity here isn't a missing feature — it's an audience. This project has built, tested against real infrastructure, and shipped a moderation queue, trust-weighted voting, anonymous submission, and a bulk-contribution flow that, as of today, no stranger has ever actually finished using end to end. That's not a criticism of the engineering; it's the clearest possible signal about where the next unit of effort should go. Before adding another mechanic to reward contributors who don't yet exist, the highest-leverage moves are the cheapest ones on this list: know whether anyone's arriving at all, and put the exact question this site answers in front of the people already asking it — in Discord, in the anime-community threads, in a bot — rather than waiting for them to find it on their own.
